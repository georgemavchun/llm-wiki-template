# FAQ

**Why markdown and git, not Notion or another wiki tool?**
Git gives you history, diffs and standard tooling for free, and markdown is something both you and the agent can read and edit directly. A coding agent is good at exactly this kind of file editing; a database-backed wiki tool would need a bespoke integration to get the same result.

**Can I use Codex or Cursor instead of Claude Code?**
Yes. Start from [../AGENTS.md](../AGENTS.md), which points at the same skill files and the same schema. Skills are plain markdown files under `.claude/skills/`. Any agent that can read a file and follow instructions can use them, mapping tool names as needed.

**Can I keep pages in my own language?**
Yes. Edit the "Language policy" paragraph in [../wiki/CLAUDE.md](../wiki/CLAUDE.md); see [customizing.md](customizing.md). Structural elements (filenames, frontmatter, headings) stay English either way, so the tooling keeps working.

**I pasted a transcript by accident. What happens?**
If it contains anything the preflight scanner recognizes, the write is blocked before anything is saved; see [privacy.md](privacy.md). If it does not trip the scanner but you realize afterward it should not be there, use the redaction procedure in the same document rather than quietly editing it away.

**Does the agent read my whole wiki every time?**
No. Every operation reads `wiki/INDEX.md` first and opens only the pages that look relevant, using `scripts/wiki_search.py` or the `wiki-scout` subagent once the index is long. That is the point of having an index.

**How big can the wiki get?**
The pattern this template builds on reports hundreds of pages working fine with just an index and keyword search. This template's own scale thresholds live in `wiki.config.json`: shard the index around 150 pages, start using `wiki_search.py` by default around 300, and subdivide a directory around 50 pages in one place.

**Can two people share one wiki?**
Not with this template as it stands; it is built around one owner making the judgment calls a personal wiki needs. For a team, use `wiki-share` to push sanitized extracts from your personal wiki into a separate team wiki, which could itself be a copy of this template, maintained by whoever owns it.

**What does "reliability" mean on a page?**
How well-supported a claim is: `high` needs two independent sources, or one primary authoritative one; `medium` is the default; `low` is a single unchecked source. It is not a measure of how important the claim is.

**What is "Pending Review"?**
A section at the bottom of a page for claims that are unverified, contradicted elsewhere, or extracted with low confidence. The agent never merges these into the main body silently; you decide when, or whether, they graduate.

**Why is raw add-only?**
So "what did the source actually say" is always answerable without trusting anyone's paraphrase of it, including the agent's own from six months ago. If a source turns out to be wrong, the correction goes on the wiki page that cites it, under Pending Review, not into the source itself.

**The hook blocked me. How do I override it, and when should I not?**
`git commit --no-verify` skips the pre-commit hook entirely. Use it only when you have already read why it blocked and are certain the block is wrong, for example a false positive on ordinary text. Never use it to push through a real finding faster; that defeats the reason the hook exists.

**How do I delete something sensitive that already got committed?**
Rotate any credential first, then see "If a secret got in" in [privacy.md](privacy.md). Deleting the current file is not enough; it stays in git history until the history itself is rewritten.

**Why is the inbox-drainer workflow off by default?**
Because running it unattended sends everything in your inbox to the model provider from GitHub's infrastructure and skips the interactive step where you could catch something before it is written. See [customizing.md](customizing.md) before turning its schedule on.

**Can I run this without Claude Code at all?**
The scripts (`wiki_lint.py`, `privacy_preflight.py`, and the rest) are plain Python and run standalone. The skills, which describe the ingest, query and crystallize workflows, need an agent that can read a skill file and act on it; Claude Code, Codex and Cursor all qualify.

**How do I get template updates?**
Watch or star the template repository, and follow [../CHANGELOG.md](../CHANGELOG.md) for what changed. Upgrading your own copy is described in [customizing.md](customizing.md).

**What does the session-start status mean?**
A one-time summary printed when you open Claude Code in the folder: page counts by family, error and warning counts from lint, how many files are waiting in the inbox, and the most recent log entry. It is generated by `scripts/hooks/session_start.py`; see [onboarding.md](onboarding.md).

**Where do temporary files go?**
`.staging/`, at the repository root, gitignored. Pasted or downloaded content waits there until the privacy preflight clears it and it can be moved into `wiki/raw/`. Nothing in `.staging/` is ever committed; the pre-commit hook refuses to.

**What if lint reports warnings I don't want to fix right now?**
Nothing forces you to. Lint only reports; warnings do not block a commit or an ingest. Fix them when the wiki-evolve nudge suggests it, or whenever you next touch the affected page.

**Do I need to write the classification ledger by hand?**
No. It is built and validated automatically as part of `wiki-ingest` when the source is a transcript. You only see the result, a classification summary, unless something is blocked.

**Can I delete a page I no longer want?**
Yes, pages are not add-only the way `wiki/raw/` is. Delete or merge it, then fix the resulting broken links and index entries; `lint the wiki` will point them out if you miss any.
